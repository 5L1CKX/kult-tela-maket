# Версионирование проекта

Проект версионируется по схеме SemVer: `vMAJOR.MINOR.PATCH`.

## Правила инкремента версий

- **MAJOR** (`vX.0.0`) — фундаментальные архитектурные изменения и смены стека:
  - перенос статического макета на фреймворк (например, Astro);
  - глобальная переработка структуры URL и дизайн-системы;
  - полный рефакторинг логики конфигурирования и интеграций.

- **MINOR** (`v1.X.0`) — новая функциональность без слома обратной совместимости:
  - добавление новых страниц (например, страницы отдельных услуг, блог, оферта);
  - подключение рабочих интеграций вместо заглушек (интеграция YClients, онлайн-эквайринг);
  - добавление новых тем, палитр или крупных блоков интерфейса.

- **PATCH** (`v1.0.X`) — правки и оптимизация существующего контента:
  - обновление текстов, контактов и ценников в каталоге;
  - замена картинок-заглушек на итоговые фотоматериалы;
  - точечные фиксы стилей (CSS) или поведения скриптов (JS);
  - исправление опечаток и верстки под специфичные разрешения экранов.

## Создание тегов в Git

Релизы фиксируются аннотированными тегами:

```bash
git tag -a vX.Y.Z -m "vX.Y.Z: Краткое описание изменений"
git push origin vX.Y.Z
```

Для отправки всех локальных тегов сразу:
```bash
git push origin --tags
```
